# SilentCKD

Finds adults with diabetes or high blood pressure who probably have hidden kidney damage, so clinics know who to send for a urine test first.

Built for DataNova 2026, problem DN-HC-01 (Early Risk Stratification for Chronic Disease). Prototype only, not a medical device.

**Try it:** https://silentckd.davidwong51423.workers.dev | **Code:** https://github.com/dismality/silentckd

## The problem
Early kidney damage has no symptoms, and the usual kidney blood test misses more than half of it. A cheap urine test (ACR) finds it, but [only 35% of people with diabetes and 4% with hypertension get one within two years](https://pubmed.ncbi.nlm.nih.gov/34365812/).

## What it does
- **Check a patient:** a Likely, Possible or Unlikely answer, the chance in 100, plain reasons, and questions for the doctor.
- **Clinic list:** ranks a whole clinic, highlights patients usual practice would skip, and plans how many tests to run and what they cost. Accepts a CSV or FHIR R4 health-record files.
- **Accuracy and fairness:** results on two test groups, 10-year outcomes, messy-record checks and results by group, including where it is weak.

## Results on 2,583 held-out patients from 2021-23
| | |
|---|---|
| AUROC | 0.754 (95% CI 0.730-0.778) |
| Calibration slope | 0.97 |
| Cases caught (Likely or Possible) | 81%, with 55% of patients flagged |
| Likely answers that were right | 65% |
| Cases found testing 1 in 5 patients | 48% vs 31% for diabetes first |

Read the [model card](docs/model_card.md), [validation report](docs/validation_report.md) (including its disclosure of how the test set was used), [comparison with existing tools](docs/related_work.md) and [deployment plan](docs/deployment_plan.md). **It finds damage already present. It has not been shown to predict new kidney disease.**

## Tested again on a locked group
On 2,469 patients from 2007-10, with the models and answer rules frozen first: AUROC 0.749 (0.723-0.774), slope 0.95, 82% of cases caught, 62% of Likely answers correct, and 47% vs 31% of cases found testing 1 in 5 patients.

Linked death records through 2019: 58, 28 and 11 deaths per 100 within 10 years for Likely, Possible and Unlikely. This is not evidence of predicting new kidney disease.

## Project layout
| Path | Purpose |
|---|---|
| `download.sh` | Fetches the NHANES files |
| `src/prep.py` | Builds the cohort |
| `src/train.py` | Trains and validates the full model, runs fairness checks |
| `src/patterns.py` | Builds similar-patient reference data for the unusual-record warning |
| `src/answers.py` | Trains the short-form model, sets the answer rules |
| `src/stress_test.py` | Extra sceptical checks |
| `src/external.py` | Locked 2007-10 test, linked mortality, messy-record simulation |
| `src/compare_published.py` | Compares with the closest published model design |
| `src/test_fhir.js` | Tests the FHIR reader on a folder of Synthea files |
| `src/retrain.py` | Retrains on a new dataset |
| `src/sync_docs.js` | Copies `docs/` files into the website before each deploy |
| `demo/` | The website; runs entirely in the browser |
| `docs/` | Model card, validation report, related work and deployment plan |
| `models/`, `metrics/`, `figures/` | Trained models and saved results |

The NHANES data is not stored in this repository because it is 163 MB. `download.sh` and `src/prep.py` rebuild it.

## Reproduce
```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
bash download.sh
cd src
../.venv/Scripts/python prep.py
../.venv/Scripts/python train.py
../.venv/Scripts/python patterns.py
../.venv/Scripts/python answers.py
../.venv/Scripts/python external.py
../.venv/Scripts/python compare_published.py
cd ..
.venv/Scripts/python src/stress_test.py
```
These commands are for Windows with Git Bash. On Mac or Linux, use `python3` for the first line and replace `.venv/Scripts` with `.venv/bin` and `../.venv/Scripts` with `../.venv/bin`.

## Run the website
```bash
python -m http.server 8765 --directory demo
```
Then open http://localhost:8765. The live copy is at https://silentckd.davidwong51423.workers.dev. To publish changes to it:
```bash
npx wrangler@4 deploy
```

## Retrain on new data
```bash
.venv/Scripts/python src/retrain.py your_data.csv --label outcome --rename SBP=sbp --rename HbA1c=hba1c
```
Add `--update-site` to load the new model into the website. Cut-offs are set on the training part only.
